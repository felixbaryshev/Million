# Бот приёма заявок

Принимает заявку в Telegram, проверяет ответы, сохраняет и сразу
присылает владельцу. Сценарий диалога описывается в YAML — под нового
клиента меняется один файл, а не код.

## Попробовать прямо сейчас

Без токена, без регистрации, без телеграма:

```bash
pip install -r requirements.txt
python demo.py
```

Диалог пройдёт прямо в терминале и покажет заявку в том виде, в каком
она уйдёт владельцу.

## Запуск бота

```bash
BOT_TOKEN=<токен от @BotFather> ADMIN_IDS=<ваш id> python -m bot.app
```

Свой id можно узнать у `@userinfobot`. Админов может быть несколько:
`ADMIN_IDS=111,222`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота, обязательно |
| `ADMIN_IDS` | — | Кому приходят заявки, обязательно |
| `SCENARIO_PATH` | `scenario.yaml` | Какой сценарий использовать |
| `DB_PATH` | `leads.db` | Где лежат заявки |

## Команды

**Для клиента:** `/start` — начать, `/cancel` — отменить,
«назад» — вернуться на шаг.

**Для владельца:** `/leads` — последние 10 заявок, `/export` — выгрузка
в CSV, `/stats` — сколько всего и сколько сегодня.

## Сценарий

```yaml
steps:
  - id: phone
    label: Телефон
    type: phone
    question: По какому номеру перезвонить?
    error: "Не похоже на номер. Напишите так: +7 916 123-45-67"
```

Типы: `text`, `phone`, `email`, `number`, `choice`.
`required: false` делает шаг необязательным.
`options` задаёт кнопки и работает только с `type: choice`.

**Конфиг проверяется при запуске.** Опечатка, неизвестный тип,
повторяющийся `id`, `choice` без вариантов — всё это валит бот сразу
с внятным сообщением. Это сделано намеренно: сценарий правит человек,
и ошибка должна найтись при запуске, а не ночью, когда её найдёт
клиент клиента.

## Что здесь решено, кроме диалога

**Телефоны приводятся к одному виду.** `8 916 123-45-67`,
`+7 (916) 123 45 67` и `9161234567` — это один и тот же номер, и в
выгрузку он попадёт как `+79161234567`. Иначе база через месяц
превращается в кашу, по которой нельзя ни позвонить скриптом, ни
найти дубль.

**Выгрузка открывается в Excel.** CSV пишется с BOM и точкой с
запятой. Без этого Excel показывает кириллицу кракозябрами, и клиент
решает, что выгрузка сломана.

**Колонки собираются по всем заявкам.** Сценарий со временем меняется;
старые заявки не должны терять поля при выгрузке.

**Недоступный админ не ломает приём.** Если владелец заблокировал бота
или сменил аккаунт, заявка всё равно сохраняется — в лог уходит
предупреждение, клиент получает подтверждение.

**Ответы не теряются на ошибке.** Неверный телефон не сбрасывает
диалог: бот повторяет вопрос и идёт дальше с того же места.

## Ограничения — честно

Состояние незавершённых диалогов хранится в памяти: при перезапуске
бота те, кто не дошёл до конца, начинают заново. Сохранённые заявки
не теряются. Для потока в десятки заявок в день это нормально; если
нужно иначе — состояние переносится в базу, это несколько часов.

SQLite рассчитан на десятки заявок в день, а не тысячи в секунду.
Для малого бизнеса это с запасом, но это не та база, на которой
строят маркетплейс.

Записи в Google Таблицы и CRM в этой сборке нет — добавляется поверх
`storage.py`, интерфейс для этого уже разделён.

```bash
pip install pytest
python -m pytest tests -q
```

95 тестов: валидация ответов, движок диалога, загрузка конфига,
хранилище и выгрузка. Телеграм для них не нужен — логика диалога
намеренно отделена от транспорта.
